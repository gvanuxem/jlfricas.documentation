JFriCAS
=======

:viewcode:`jfricas.spad line 87 <jfricas.spad#L87>` :editcode:`[edit on github] <jfricas.spad#L87>`


The JFriCAS package contains functions to start a webserver and to initialize ioHooks for the communication between FriCAS and the Jupyter frontend. It also manages the communication between FriCAS (via the Hunchentoot webserver) and the Jupyter notebook.

.. index::
   pair: JFriCAS; handleOutput

:spadfun:`handleOutput`\: (\ :ref:`Boolean <l426f6f6c65616e>`\ , \ :ref:`String <l537472696e67>`\ ) -> \ :ref:`String <l537472696e67>`\  
  \ :code:`handleOutput(err?, out)`\  translates the output out into a string that contains a JSON structure that is to be understood by fricaskernel.py. The function interprets the "--FORMAT:BEG:"/"--FORMAT:END:" pairs, in particular reads off the step number from their end and groups the output into substructures indexed by the step number of FriCAS. The JSON record looks like {"error?": \ :code:`true`\ , "souts": [\ :code:`s1`\ ,..., \ :code:`sn`\ ]} where 'error?' is either True or False (depending on whether or not the evaluation produced an error) and the responses \ :code:`si`\  are dictionaries that represent stepped outputs, \ :code:`i`\ .\ :code:`e`\  are of the form {"step": step, "outs": [\ :code:`o1`\ , ..., om]} and the \ :code:`oi`\  are of the form {content_type: content}. Note that content_type can be "ERROR", which means that the respective content is an error message or is content that was outside of \ :code:`e`\  "--FORMAT:BEG:"/"--FORMAT:END:" pair.
